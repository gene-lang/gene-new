## Approved non-idle baseline

The design originally required a one-minute load below 1.0 before and after
five runs. Unrelated host workloads prevented that condition; the owner
explicitly approved using non-idle measurements for this milestone on
2026-09-29. These results are the approved baseline, with host contention
recorded as a limitation. Future comparisons should use an idle host or a
similarly controlled load rather than assume these are idle-machine timings.

## Bounded candidate assessment

Candidate: cache repeated name lookup in the hot `Scope.lookup` path. The
direct `lookup` entry has 361 self samples (2.9%); `hash`, `memcmp`, and call
scope binding add potentially related time, although the sample does not
attribute all of those to name lookup. A lookup cache needs invalidation for
slot redefinition, dynamic `eval`, imports, wildcard ambiguity, and parent
scope mutation. `Scope.lookup` checks these in order, so a local hash shortcut
would risk changing visibility or error behavior. No safe, bounded change was
identified from this profile. This milestone retains the baseline and profile
without a speculative runtime patch; a measured inline-cache design belongs
in a separate follow-up.
