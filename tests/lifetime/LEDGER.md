# Native VM lifetime evidence ledger

This ledger implements VM-0 from [the reliability proposal](../../docs/proposals/vm-reliability.md). It records what a probe actually covers. A passing row does not qualify unrelated value classes, the threaded runtime, or a sustained service.

| Class | Owning and borrowed edges to inspect | Probe | Current evidence | Remaining qualification |

| Closures and scopes | Scope bindings own functions; captured-scope edges may be weak until a closure escapes. | `nimble leakcheck` closure/scope cases in `tests/test_rc.nim` | Existing focused cases pass on the current ORC build. | Mixed graphs outside those fixtures need an edge inventory and retained-control checks. |
| Nominal Types and protocol implementations | Type owns methods and signatures; methods can retain their declaration scope. Built-in protocol implementations are read by worker lanes and their Value edges need atomic RC after publication. | `tests/profiles/native-app/lifetime/src/batches.gene` repeats a fixed eval-defined Type/method alongside closure, cell, self-cycle, impl-runtime-failure, and compile-failure forms. `src/witnesses.gene` retains one Type and releases 10,000 ValueEq/Hash/Order Types. `src/cancellation.gene` cancels a child only after its Type/ValueEq impl has been created and the child is parked. `test_native_api_threads.nim` concurrently admits shared errors. | The RC-enabled macOS arm64 batch, witness, and cancellation processes held 881, 822, and 794 managed values respectively at warm-up and every 1/100/1,000/10,000 checkpoint. All seven per-class counts were identical within each process, native roots were zero, and both retained controls executed. The cancellation process had zero root Tasks after every batch. AddressSanitizer found a use-after-free in a built-in native function during concurrent protocol lookup on the baseline (2/30 plain runs failed); publishing built-in impl values fixed the reproducer in 100/100 sanitizer and 100/100 plain runs, and `nimble threadcheck` passed. | Other cancellation boundaries, module reload, mixed RC/Nim scope graphs, and native x86_64 Linux qualification remain. |

The RC-enabled scalar and Type/protocol/impl children held 820 managed values at warm-up and after 1/100/1,000/10,000 more releases; the failure child held 822 (baseline grew 15 per release and 30 per failure iteration). Ten adversarial retention shapes (Type, instance, closure over a cell, enum variant, Protocol, Enum, registry map, `this_mod` function, Module, alias), a two-module generation with a cross-module Type, and a module that releases its own generation ran clean under AddressSanitizer. | `#Ref` tables and entries are graph nodes with ORC totals (every scope that ran a `#Ref` chunk shares its root's table), and the VM enumerates a fresh or yield-suspended generator Fiber through an installed adapter; a Fiber with task, actor, wait, pending-unwind, ensure/for, or frame-extra state stays opaque. Other unenumerated edges (compiled-code constants, error evidence, `RootRef` state) keep their targets alive, so such generations are retained rather than reclaimed; a leak matrix of `#Ref`, error values, annotated constructors, cells, closures, namespaces, event buses, Envs, and generators is flat. So are generations holding a generator paused at `yield` inside `for`, inside `try`/`ensure`, while iterating another generator, or after reading a channel. A generator parked on a Task or channel when its generation is released is held by the scheduler's waiter list, so that generation is retained, as it should be. AtomicArc builds, where Gene worker lanes exist, and the wasm module skip retirement; AtomicArc retirement is a separate qualification task. Until `config.nims` took over the ORC pin, `--mm:atomicArc` builds also defined `gcOrc`, so earlier AtomicArc evidence came from a hybrid runtime. Retirement runs only when a generation is released, discarded, or fails preparation, when a module reload starts, and at the test collection point, so a generation whose last outside owner drops later waits for the next of those. A reload cannot retire the root it replaces, because its own rollback copies still hold that root; the next reload or release does. Whole-pending analysis runs without yielding under the module-mutation pause: about 6 ms extra for a 10,800-node generation in the debug RC build. On Linux x86_64 under Rosetta the ORC-header layout probe passes and the generation children hold the macOS counts; native x86_64 is unqualified. |

Baseline invocation: `nimble leakcheck` runs the ORC build with `geneRcStats`. The profile probe uses `python3 tests/profiles/native-app/run.py --probe-blocked --workload lifetime`; it builds a separate test-only `geneRcStats` ORC binary, runs eight fixed-vocabulary child processes (batches, witnesses, cancellation, partial selections, in-process service requests, scalar generations, Type/protocol/impl generations, and discarded/failed generations) plus retained module, function, and instance controls, and records its SHA-256, compiler, flags, pinned SDK, platform, sampled RSS, warm baselines, and batch snapshots. Each process has a hard deadline and returns the last progress marker on timeout. `probe_pass` remains a probe because other mixed graphs, longer sustained-service runs, and native x86_64 Linux gates are not yet satisfied.

`$runtime/gc_stats` now distinguishes counted manually managed classes, explicitly unreleased GeneRoot handles, pending `io_root_tasks`/`io_root_cleanup_tasks`, open native test/file/CSV reader resources (`io_csv_open_resources`), CSV parser payload lengths (`csv_parser_retained_bytes`, `csv_parser_peak_resource_bytes`), and the IO lifecycle budget's `io_retained_bytes`, `io_peak_retained_bytes`, and `io_cleanup_leases` from uninstrumented aggregate `cleanup_leases` and cycle candidates. The CSV counters omit allocator capacity and object overhead. A nil field is missing evidence, never a zero. Counts for Nim-managed scopes and native allocations are not implied by the manually managed total. The scope boxed-edge walk now includes wildcard fallbacks, type bindings, pending types, module refs, supervisor values, and owned task/actor roots; it does not inspect arbitrary `RootRef` or Nim Scope owners.

Next VM-0/3 probes: retain and release module generations across repeated local eval, and compiled-code constant and error-evidence edges in retired generations (matrix probes so far are flat). The batch fixtures keep source vocabularies bounded and each child process under a hard deadline.
