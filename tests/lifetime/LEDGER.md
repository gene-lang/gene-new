# Native VM lifetime evidence ledger

This ledger implements VM-0 from [the reliability proposal](../../docs/proposals/vm-reliability.md). It records what a probe actually covers. A passing row does not qualify unrelated value classes, the threaded runtime, or a sustained service.

| Closures and scopes | Scope bindings own functions; captured-scope edges may be weak until a closure escapes. | `nimble leakcheck` closure/scope cases in `tests/test_rc.nim`, including the child-scope cycle, returned-value, kept-closure, and deep tail-recursion cases. | A closure that captured a scope or one of its loop, `match`, or call child scopes, held directly or in a list, map, node, or Cell by that scope's bindings, closes scope → value → closure → scope; the weak back-edge covers only a function bound directly in the scope it captured. Before this repair, per 1,000 calls of the enclosing function, a `for` or `match` closure stored in an outer `var` leaked 1,000, three `for` closures pushed into an outer list leaked 4,000, and `(var hs [(fn [] 1)])` leaked a list and a function per call. The earlier notes blamed the scope pool; the probes showed the open shapes ended in a tail call, which replaced the frame without a check. A scope is now checked (`callScopeMayCycle`, then VM-2 trial deletion with the ending register as a known owner) wherever its activation ends: a return, including the Int fast return; a tail transfer; an error, panic, cancellation, or `return` unwinding past it; a function a native calls back; each loop iteration, including `continue` and `break`; and a task's root activation. A tail call whose callee still reaches a scope that may cycle keeps its frame. A same-scope recursive call returns into a frame that still owns its scope and is not checked. When the value a call returns is what still reaches the cycle, a dry run decides whether the scope would retire without that value's outside references; if so the value (list, map, node, function, or Cell) is watched, and releasing it down to its references from inside the cycle, or freeing it, queues a recheck that the next unpooled return or run exit drains (`watchReturnedCycle`, `drainCycleRechecks`). Forty probe shapes (tail calls, fast returns, unwinding, native callbacks, nested loops, containers, Cells, returned values, generators, tasks) hold flat on an RC build and run clean under AddressSanitizer; kept closures stay callable; a 100,000-deep tail recursion binding a loop closure per level is flat. Against `e55655e`, release builds of fib, a closure factory, loops, and tail calls from unpooled scopes run at parity or faster (the baseline ran the return check on every same-scope recursive return). Reclaiming costs time where cycles used to leak: 20,000 levels of tail recursion binding loop closures took 35% longer, and a function returning a list of loop closures 47% longer. | Closures copy only immediate, Str, or Sym captures (`CapturePlan`, see VM-2). Copying a stable binding to a mutable object regressed retirement: the object could later hold the closure, closing a cycle through the copied scope rather than its ended activation. Cell/list/map/node and combined-graph regressions fail on `2439442` and pass when these captures stay by reference; retained controls still execute. Inert-capture loop shapes still avoid retirement. A closure keeps capturing by reference when it reads a binding that is assigned anywhere in its unit, redefined by a loop sharing its scope, bound by name, or reached by `env`/`eval`, or when its scopes declare types or own tasks. For those, a cycle whose last outside owner is not the returned value (a closure also stored in a global registry and removed later) is not revisited, and neither is one whose owner lets go outside the VM. The pre-check does not look inside Envs, streams, Tasks, sets, or hash maps. Generator and actor scopes are not checked. |

The profile probe uses `python3 tests/profiles/native-app/run.py --probe-blocked --workload lifetime`; it builds a separate test-only `geneRcStats` ORC binary, runs ten fixed-vocabulary child processes (batches, witnesses, Type cancellation, mixed cancellation, partial selections, in-process service requests, cancelled service requests, scalar generations, Type/protocol/impl generations, and discarded/failed generations) plus retained module, function, and instance controls, and records its SHA-256, compiler, flags, pinned SDK, platform, sampled RSS, warm baselines, and batch snapshots. Each process has a hard deadline and returns the last progress marker on timeout. `probe_pass` remains a probe because other mixed graphs, longer sustained-service runs, and native x86_64 Linux gates are not yet satisfied.

`$runtime/gc_stats` now distinguishes counted manually managed classes, explicitly unreleased GeneRoot handles, pending `io_root_tasks`/`io_root_cleanup_tasks`, scheduler-owned `io_read_guards` (pending protocol reads and upload borrows), queued `scheduler_runnable_fibers` and parked `scheduler_waiting_fibers` (excluding the executing Fiber), open native test/file/CSV reader resources (`io_csv_open_resources`), CSV parser payload lengths (`csv_parser_retained_bytes`, `csv_parser_peak_resource_bytes`), and the IO lifecycle budget's `io_retained_bytes`, `io_peak_retained_bytes`, and `io_cleanup_leases` from uninstrumented aggregate `cleanup_leases` and cycle candidates. The CSV counters omit allocator capacity and object overhead. A nil field is missing evidence, never a zero. Counts for Nim-managed scopes and native allocations are not implied by the manually managed total. The scope boxed-edge walk now includes wildcard fallbacks, type bindings, pending types, module refs, supervisor values, and owned task/actor roots; it does not inspect arbitrary `RootRef` or Nim Scope owners.

Next VM-0/3 work: closure cycles whose outside owner is not a returned value, and the container kinds the pre-check skips (Closures and scopes row); then compiled-code constant and error-evidence edges in retired generations (matrix probes so far are flat). The batch fixtures keep source vocabularies bounded and each child process under a hard deadline.

## Protocol read admission

The owned Client and canonical AsyncReader dispatch share scheduler-owned reader/Task pins. Custom-reader RC tests require zero guards and a flat managed count after repeated completed reads. Owned-Client tests cover pending-read admission, held/dynamic/pipeline/inherited reads, delayed cancellation cleanup, budget rollback, and parent delegation; the AtomicArc case exercises worker-pool integration. Completed pins retire on the root lane outside its lock. Native physical tickets remain lifecycle-owned; custom convenience methods/backend aliases are outside the protocol guard. See [the borrowing audit](../../docs/profiles/native-app.md#async-io-and-borrowing).

The borrowing continuation's full profile is `probe_pass`; the ten-child lifetime binary SHA is `af0cdfcd7494c7b9e6c762f56ebefd1ddaa283245f55d97a4d6eadb83c840088`. Mixed/HTTP baselines are 931/1046 and stay flat through 10,000 batches, with zero read guards and existing zero queue/byte/lease/readiness counters. Retained generation controls pass. The 60-second SERVICE run has heartbeat 54 ms and managed growth 0; sustained qualification remains separate.


## AtomicArc generation experiment

The [AAR-0 design](../../docs/proposals/atomic-arc-retirement.md) remains opt-in;
normal AtomicArc generation/activation retirement is disabled. Independent
one-word/three-bit header checks and a paused-root guard qualify private
namespace/scalar generations through 10,000 retirements and private Type/direct
method release/discard/failure through 1,000 batches. Per-class counts are flat;
retained private roots and instances stay usable until dropped. The later
[publication continuation](../../docs/profiles/native-app.md#atomicarc-retirement)
conservatively pins SDK roots even after release because raw returned Values
have no reported borrow lifetime.

Published Values and known defining Scopes stay pinned. Published pending roots
retain the whole batch without enumerating their mutable tables. Five canonical impl generations retain 63 managed
Values and pending roots in the explicit `qualified: false` control; dropping
a named reader cannot qualify shared collection. Foreign admission/borrow
fences and arbitrary Nim ref transfers remain AAR-1/2 work.

The [native admission continuation](../../docs/profiles/native-app.md#atomicarc-retirement)
adds qualification-only entry leases for SDK roots and native modules. Counting
requires a drained native boundary after the worker pause. Owner-dependent calls
defer collection; native admission reopens after Scope edges detach and before
cleanup, while a collector reservation prevents overlapping passes. Raw returned
objects keep their permanent pins. Full managed borrows and other native API
paths remain unqualified; this does not promote AAR-2 or production retirement.

ThreadSanitizer exposed worker allocator access after an early inactive marker.
Nested pause depth and teardown-aware retiring slots now acknowledge only after
local/scheduler Fiber owners release, outside the scheduler lock. An owned copy
and explicit reset avoid Nim's temporary overwrite; the existing typed-Task
string lifetime case passes. Instrumented counters are atomic under threads.
The Gene runner's disabled/probe/ASAN/TSAN modes pass; targeted TSAN covers running
workers and a concurrently reading native thread. Default threadcheck, ORC
leakcheck and spec pass. See [the audit](../../docs/profiles/native-app.md#atomicarc-retirement).
