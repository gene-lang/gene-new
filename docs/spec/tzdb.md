# Experimental `genex/tzdb`

`genex/tzdb` is an optional, independently locked Gene package. Version 0.1.0
ships 597 compiled zone files from IANA release 2026d as format-1 package
resources. The runtime reads only those selected Bytes; it does not consult
the host timezone database or process `TZ`. The package exposes `release_id`,
`to_local instant zone`, and `resolve_local datetime zone ^fold "reject"`.

`to_local` requires an offset DateTime representing an instant. `resolve_local`
requires an offset-free DateTime representing wall-clock fields. Unknown zones,
nonexistent local times, and ambiguous times with the default `reject` fold
fail. `earlier` and `later` select the earlier or later UTC instant at a fold.

Both conversion functions return a Map with `datetime`, `instant` (UTC),
`offset_seconds`, `zone`, and `tzdb_release`. Whole-minute offsets appear on
the DateTime with its zone annotation. Historical offsets containing seconds
cannot fit Gene DateTime's minute-precision offset field: in those records,
`datetime` has exact offset-free local fields, while `instant` and
`offset_seconds` retain the exact interpretation. Consumers must keep the
record together when persisting such an interpretation.

The TZif v2–v4 reader bounds file and table sizes, checks transition order and
type indices, and applies the POSIX footer after the last explicit transition.
Leap-second TZif files are unsupported; the shipped IANA package uses the
ordinary non-leap zone files. A package update is a separate locked release;
an installed application's bundled resource closure remains authoritative.

`tests/test_tzif.nim` validates every packaged file against 3,582 offsets
generated by Python `zoneinfo.from_file` from the same pinned bytes. The
installed-app test covers the release ID, current and historical offsets,
future rules, fold/gap behavior, source-package replacement without changing
the installed interpretation, and execution without the source checkout or a
compiler. Linux runtime qualification remains open.
